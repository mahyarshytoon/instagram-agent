🗺️ جلسه ۱: نقشه‌ی پروژه

🎯 هدف این جلسه

فهمیدن سفر یه کامنت — از لحظه‌ای که کاربر کامنت می‌ذاره، تا لحظه‌ای که جواب می‌گیره.

مک‌دونالدز رو تصور کن: 
۱. مشتری میاد تو
۲. صندوق‌دار سفارش می‌گیره
۳. سفارش می‌ره آشپزخونه
۴. آشپز برگر می‌پزه
۵. غذا میاد رو پیشخوان
۶. صندوق‌دار صدا می‌زنه: «سفارش شماره ۴۲!»
۷. مشتری می‌گیره و می‌ره

پروژه‌ی تو هم دقیقاً همینه، ولی برای اینستاگرام!

🗄️ جلسه ۲: دیتابیس

🎯 هدف این جلسه

فهمیدن چرا ۲۶ جدول داری و هر کدوم چرا وجود داره.

یه کتابخونه بزرگ رو تصور کن:
  • قفسه = Table (جدول)
  • کتاب = Row (ردیف)
  • عنوان، نویسنده = Column (ستون)
  • نقشه‌ی چیدمان = Migration
  • کتابدار = Model

📊 سه مفهوم پایه

مفهوممعنیمثال
Tableقفسهproducts
Rowکتابکرم ضد آفتاب
Columnویژگیname, price

🎯 سه سؤال که Migration جواب می‌ده

❓ چرا Migration؟

  • تکرارپذیری
  • تاریخچه
  • هماهنگی تیم
  • تست آسون

❓ چرا Model؟

  • خوانایی
  • امنیت (SQL Injection)
  • رابطه راحت
  • تست راحت

❓ چرا Relationship؟

  • اتصال جدول‌ها
  • جلوگیری از تکرار
  • DRY
  • نرمال‌سازی

📊 سه نوع Relationship

نوعمثالFK کجا؟
۱ به ۱User ↔ Profileیه طرف
۱ به NUser → Commentsطرف «چند»
N به MPost ↔ Productجدول واسط

🎯 State Machine کامنت‌ها

🟡 pending    ← تو صف
    │
    ├─→ 🟢 processed  (AI جواب داد)
    ├─→ ⚪ skipped    (محصول نبود)
    ├─→ 🔴 rejected   (اسپم بود)
    └─→ ⚫ failed     (خطا داد)

🎯 قانون DRY

«اگه چیزی رو می‌تونی از جای دیگه بفهمی، تو ذخیره نکن!»
❌ تکراری✅ جای درست
کاربر تو responsesاز comment_id بگیر
قیمت تو instagram_postsتو products
لیست کامنت‌ها تو usersFK تو comments
📌 قانون طلایی: «قبل از اضافه کردن FK، بپرس: - می‌تونم از یه راه دیگه بهش برسم؟ - اگه بله، نذارش!»

🚪 جلسه ۳: Webhook

🎯 هدف این جلسه

فهمیدن چطور Meta به ما وصل می‌شه.

دو تا راه برای گرفتن خبر:

روش ۱: Polling (زنگ زدن مداوم) 
تو: «سلام، کامنت جدید اومده؟» (هر ۵ دقیقه)
Meta: «نه»
تو: «سلام، کامنت جدید اومده؟»
Meta: «نه»
تو: «سلام...»
Meta: «آره، ۱ دقیقه پیش اومد»
روش ۲: Webhook (خودش خبر می‌ده) 
تو: «آقای Meta، اگه کامنت جدید اومد، خبرم کن»
Meta: «باشه»
...
Meta: «سلام! کامنت جدید اومد»

🎯 سه مفهوم کلیدی

🌐 Endpoint

چی: آدرسی که Meta بهش POST می‌زنه

کجا: routes/api.php

آدرس: POST /api/instagram/webhook

🔐 Signature

چی: یه کد مخفی که ثابت می‌کنه درخواست از Meta اومده

چطور: HMAC-SHA256 با APP_SECRET

✅ 200 OK

چی: جوابی که همیشه برمی‌گردونیم

چرا: اگه 500 بدی، Meta دوباره می‌فرسته (اسپم)

🎓 نکته: 200 یعنی «گرفتم» نه «انجام دادم»

پستچی نامه می‌آره: 
📬 پستچی: «نامه رو بده به تو»
👤 تو: «باشه گرفتم» (200 OK)
    ↓
    ولی هنوز نامه رو باز نکردی!

200 یعنی: «دریافت کردم، می‌رم پردازش کنم»

نه یعنی: «پردازش شد»

📬 جلسه ۴: Queue

🎯 هدف این جلسه

فهمیدن چرا کار پس‌زمینه مهمه.

مک‌دونالدز:

❌ اشتباه:

مشتری: «برگر»

✅ درست: 
صندوق‌دار: «سفارش شما؟»
مشتری: «برگر»
صندوق‌دار: «۴۲، برو کنار، صدا می‌زنم»
(آشپز می‌پزه، بعد صدا می‌زنه)

❌ تلاش ۳ (شکست) → صبر ۹۰۰ ثانیه

🧠 جلسه ۵: AI + RAG

🎯 هدف این جلسه

فهمیدن چطور AI جواب دقیق می‌ده.

فروشنده‌ی جدید رو تصور کن:
  • هیچی از محصولات تو نمی‌دونه
  • باهوشه (مثل ChatGPT)
  • ولی اطلاعات نداره

اگه بگی «قیمت کرم ضد آفتاب چنده؟»:

❌ فروشنده‌ی بدون اطلاعات:
«نمی‌دونم! من فقط یه مدل زبانی‌ام.»

✅ فروشنده‌ی با RAG:
(میره تو دفترچه، قیمت رو پیدا می‌کنه)
«۲۵۰ هزار تومن.»

🔌 جلسه ۶: Adapter Pattern

🎯 هدف این جلسه

فهمیدن چطور بدون تغییر کد، بین Fake و Real سوییچ می‌کنی.

مبدل برق رو تصور کن: 
🔌 پریز ایرانی → 🔌 مبدل → 🔌 پریز اروپایی

چون پریز ایرانی با دوشاخه‌ی اروپایی نمی‌خوره، مبدل واسطه می‌شه.

🎯 مشکل چیه؟

🌐 تو ایران هستی
📱 Meta تحریمه
❌ نمی‌تونی وصل شی

راه‌حل: FakeMetaServer!

🎯 سه فایل تو پروژه

فایلکارش
MetaAdapterinterface (قرارداد)
FakeMetaAdapterبرای توسعه
RealMetaAdapterبرای تولید

🎯 تفاوت Interface و Class

InterfaceClass
📋 «هر کسی می‌تونه»👤 «من می‌کنم»
«چی» رو تعریف می‌کنه«چطور» رو تعریف می‌کنه
نمی‌دونی چطورمی‌دونی چطور

🎯 سوییچ چطور؟

// تو .env:
META_ADAPTER=fake    # توسعه
META_ADAPTER=real    # تولید

// تو MetaServiceProvider:
$this->app->singleton(MetaAdapter::class, function () {
    return config('admin.meta.adapter') === 'real'
        ? new RealMetaAdapter()
        : new FakeMetaAdapter();
});
